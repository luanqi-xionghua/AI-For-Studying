## A. 真实模型出题失败

**现象**：deepseek-flash（思考「中」）出题时 4 批全部「模型返回的不是有效的 JSON」，0/20；抓到的批次正文只有一句旁白。1.2.4 用 deepseek-chat 能出 15/20。

### A.1 模型与参数核对

- `GET /models` 只返回 `deepseek-flash`（DeepSeek-V4.1-Flash，思考档 low / high / max，支持图片）与 `deepseek-v4-pro`（思考档 low / high / max，仅文字）。`deepseek-chat` 不在列表里，但请求仍被接受（非思考的旧别名）。两者**不是同一个模型**。
- 应用里 `deepseek-flash` 的强度表是 `none / low / high / max`，没有 `medium`。`effortForModel` 会把「中」回退成模型默认的 `high`，所以用户选「中」实际发出的是 `thinking: enabled` + `reasoning_effort: high`（模型按钮上显示「（high）」）。API 本身也接受字面的 `medium`（见 E1 第 7 行）。
- Harness 链路核对：`ai/exam.ts` 传 `maxTokens` → `providers.mjs` 透传 → Python 原样转发 → `harness/runtime.mjs`（打包版 `harness/dist/bin/worker.mjs` 里同样有）→ dsh-llm → pi-ai `max_tokens`；上下文窗口默认 1M，不会被夹小。另：`runtime.mjs` 只在 `error` / `aborted` 时抛错，**`finish_reason=length` 会被当作正常结束**，被截断的一轮静默返回。

### A.4 结论

不是「模型把 JSON 放进了 reasoning」：12 次单发里正文都在 content，只有 v4-pro 低档在思考里打了一份草稿，正文照样完整。失败有两种，都发生在工具循环的**最后一轮**：

1. **截断（思考吃掉输出上限）**：思考和正文共用 `max_tokens`。单发时 flash「高」在 4096 被截断，v4-pro「高」在 8192 时 8192 个 token 全是思考、正文为空；真机第 4 批最后一轮用了 10 329 个输出 token，在 1.2.5 的 8192 上限下会被截断。`runtime.mjs` 把 `length` 当正常结束，状态机只看到半截或空正文 →「不是有效的 JSON」。
2. **工具轮用尽后模型仍在「调工具」**：模型用满 8 轮工具（13 次调用，远超提示里的「最多检索 4 次」），最后一轮请求里已经不带工具，DeepSeek 就把自己的工具调用标记（`<｜｜DSML｜｜ calls>…`）当普通正文吐出来，前面只有一句旁白。这就是「抓到的批次正文只有一句旁白」。

对 deepseek-chat（非思考）两种情况都少见，所以 1.2.4 能出 15/20；换成思考「高」的 flash 后两种情况都会出现，第 2 次尝试仍是新会话、同样的路径，所以 4 批都失败。

### A.5 修复（只改 `ai/exam.ts` 与 `exam/*`，没动 harness / document-chat / providers）

1. **按思考档留输出余量**（`examMaxTokens`）：开了思考（low / medium / high）→ 16 384，xhigh / max → 32 768；只对已知上限足够大的 deepseek / openai / anthropic / glm 放大；不分档的模型、自定义接口保持 8192。规划与出题都用它。
2. **收尾调用**：工具循环结束而正文里没有 `{"questions"…}`（只有旁白、被截断，或工具预算用尽报错）时，用本批已读到的原文（onEvidence 收到的段落，正文为空时改用 pdf_read 的返回值；每段 ≤ 1200 字、合计 ≤ 30 000 字）发一次**不带工具**的 `streamChat`，提示「检索已经结束，不能再调用工具，只输出 JSON」。新会话没有工具历史，模型就不会再吐工具标记。收尾不算一次新的尝试；鉴权 / 网络等其他报错、用户停止、超时、超长都不收尾。
3. **单批失败不拖垮整卷**：原逻辑已保留其余批；另修 C2（失败批次从 `meta.batches` 恢复，作答页也能单批重试）。
4. 用量：每次模型调用按轮累加后记一次，并回报给状态机（N2）。

## C. 逐条排查

### C1 失败后阶段文案残留「正在准备出题…」 —— 中 · 已修

- 复现：任意一批都失败（或规划失败）后停在出题区。
- 根因：`ExamPage.vue` 的 `phaseText` 只看 `phase`：`idle` 且没停就写「正在准备出题…」；规划失败时 `phase` 还停在 `plan`，会一直写「正在规划试卷…」。
- 修复：文案移到 `exam/progress.ts` 的 `generationPhaseText`，只有 `running` 时才说「正在…」；失败 →「出题失败。」，有失败批次 →「出题未完成：第 n 批生成失败，已生成 x/20。」，停止 →「已停止出题。」，等降级决定 →「已暂停：没能读取原文…」，刷新后的半成品 →「出题未完成：已生成 x/20，可以继续出题。」。

### C2 刷新后失败批次丢失，单批重试按钮消失 —— 高 · 已修

- 复现：某批两次都失败、其余成功（例如 15/20）→ 刷新。
- 根因：① `state.generation.failedBatches` 只在本次运行中累加，`open()` 不从 `meta.batches` 恢复；② 更早的问题：部分成功时状态机直接切到作答页，而重试按钮只画在出题区，所以**不刷新也看不到**；③ 单批重试成功后不从列表里删掉该批。
- 修复：`open()`（没有在出题时）从 `meta.batches` 的 `failed` 恢复失败批次、已停止、已生成 n/m；每轮出题开始时只保留本轮不重试的失败批次，成功后删除，结束时再以 meta 为准同步一次。**设计说明**：作答页在「本卷共 15 题…」下面加一行「第 4 批生成失败：可以先作答，重新生成不影响已作答的题。」和「重新生成第 4 批」按钮（交卷后不显示）——这是让已有的单批重试在部分成功时可达的最小改动，没有新增功能；如不认可可以只保留恢复逻辑。
- 真机：开发副本里 1.2.5 留下的 15/20 卷，刷新后作答页出现「重新生成第 4 批」（截图 `c2-taking-retry-after-reload.png`）。

### C3 导出确认文案 —— 低 · 已修

- 复现：只有大题未自评时导出 →「还有 0 题未作答、3 道大题未自评…」。
- 修复：`exportPendingMessage`：两类都有时与 9.3 一字不差；只有未作答 →「还有 a 题未作答。仍然导出的话，这些题会标为「未作答」。」；只有未自评 →「还有 b 道大题未自评。仍然导出的话，这些题会标为「未自评」。」（与导出文件里大题写「未自评（按 0 分计）」一致）。真机两种都看过。

### C4 `MarkdownAnswer` 放在 `<button>` 里 —— 中 · 已修
